# 面试回答有效性审查与 IPA 覆盖（2026-11-08）

## 机制

面试官的新发言不直接重置已有答案。DeepSeek Flash 在同一次请求里读取历史对话、实际已说内容、完整现有答案与未读部分，先输出严格 JSON 的 keep/replace 控制行；判断依据是答案是否仍足以回应当前要求。已覆盖的真实追问也应 keep，不能根据附和词或句子长短分类。

keep 保留正文、answerID、朗读位置和历史，不新增回答行。replace 在同一条响应的控制行后直接流式输出新稿，不再发第二次生成请求；首个可显示片段到来前保留原稿。正在输出的已有答案允许完成，再审查后续发言；手动提问仍可强制重新生成。

审查输出不显示给用户。格式错误、请求失败保留原稿；更新的面试官输入使旧审查失效，候选人的新发言或进度使旧 replace 失效并安排重新审查。云端审查期间本机跟读可继续处理；如果正文开始前已有新的朗读进度，旧替换结果会失效并重新判断。Gemma 不再承担答案有效性审查。

## 音标

打包约 6.5 万条离线英式 IPA 词条，保留技术词覆盖。取消每篇五词上限，为非基础正文词的每次出现标注；基础词、代码、网址和标识符不密集标注，词典未覆盖的词保持原文。对应大陆高一阅读辅助的宽松策略，并非官方年级词表分级。

词典固定版本、来源与 MIT 许可证见 [词典说明](../../Resources/pronunciation/README.md)。查询不联网，生成前后台预热。显示音标不计入实际朗读词序、翻译与上下文文本，回归同时检查流式词边界和代码路径保护。
