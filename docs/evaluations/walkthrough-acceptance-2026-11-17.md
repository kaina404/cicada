## 方法

- 开发版（`scripts/build.sh`），`tools/mock-interviewer.py` 通过 `lsctl` 注入面试官原话（`themSaid`）、候选人原话（`meSaid`）、白板文字（`coachOCR`）和真实白板图片（`coachBoard`，P0 录像帧），读取 `coachCardState`。
- 结构检查由程序判定；语义检查由 DeepSeek 判卷（PASS/FAIL + 理由）。
- **没有覆盖**：真实声音（ASR、按声音判停）、真实共享屏幕、真人跟读。文字注入不能代替真人使用验收。

## 实测中发现并修复的问题

1. 模型把协议标记写成 `<<<CICARD>>>`，整张卡被丢弃 → 解析器接受任意 `<<<…>>>` 或直接以段落开头。
2. 改名基于模型自己上一张卡的建议，而不是白板上的代码 → 提示词要求一切修改以白板可见代码为准。
3. 白板触发的卡片自己发明需求（加载 / 错误状态），并记成面试官的约束 → 提示词禁止擅自加范围；约束只能记双方说过的话。
4. “Could we use Flow?” 被记成采用 → 程序保护：试探性问句不能作为 adopt 的证据（AC-04 记录层已守住，卡片文字靠提示词）。
5. 纯概念题、讲解现有架构图时画 ASCII 图 → 没有白板时丢弃 draw；面试官只要求讲解时丢弃 draw。
6. “一句话”给了三句；空的 TYPE 显示空代码卡 → 提示词限定句数；解析时丢弃空 TYPE。

7. AC-13 复述候选人：只改提示词无效 → 候选人说过话后的卡片先经过一次定向复核（删掉复述的句子；不剩内容就只给一句新信息），复核前不上屏。
8. AC-10 换题没记录：第一题的卡片被第二个问题作废、模型又把第一题记成追问 → 面试官明说“新问题 / 先放一放 / 回到…”时由程序补记；同一目标的新题视为回到原题；未知编号按目标内容匹配。
9. AC-06 澄清太长 → 限定一句、15 词以内、不列选项。
10. 紧凑窗口里代码卡被滚出视野 → 写的阶段自动滚到代码卡，新卡片开始时显示卡片头部。

## 界面实测（真实窗口）

- 浮动回答窗口，中文与英文界面各截一次：写的阶段自动滚到代码卡，代码、“替换 · 位置 · 现在写 / Replace · At · Write now”、“然后 / Then”、“下一步 / Next Step”、“之前的卡片 / Earlier cards”都正常显示，英文没有撑宽。
- 截图时临时打开笔记窗口的共享可见性，截完恢复；界面语言、字号和不透明度均恢复原值。

## 已知局限

- 每个剧本只跑了一轮（AC-10 三轮）；模型输出有随机性，单轮全过不等于每次都过。
- 定向复核会让“你说过话之后”的卡片多一次模型调用（不影响面试官提问后的首句）。
- 没有覆盖真实声音（ASR、按声音判停）、真实共享屏幕和真人跟读。
- 测试在开发版里留下了若干测试会议记录（只在开发版，与正式版隔离）。
