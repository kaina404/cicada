# ActAI 钱包面试：代码补漏必答点

2026 年 11 月 19 日。Cicada macOS Dev 1.10.1。题档、Founder 动态追问、两处改题、严格评委和真实声音（`AUDIO=1`）都与 [1139 轮](../wallet-live-20261119-1139/report.md) 相同。1139 是修复前的基线，之后四轮（1233、1307、1339、1413）边测边改。

## 改了什么

固定漏点都写在话题提示里，模型照样漏，所以这次不再加提示，改成在代码里补：卡片生成后，`CoachRequiredPoints` 按题型检查必答点，缺哪点就在卡片末尾补一句。具体做法：

- **触发**
  - 只有几类题会触发检查：丢响应和杀进程、并发转账、切换账号、群聊或 Agent 发起付款、灰度时待确认激增、澄清钱包需求、画客户端和服务端的架构图、“怎么知道改动有效”。
  - 钱包相关的规则还要求题目或当前问题的目标里出现钱包话题。这样笔记 App 的并发问题、行程规划 Agent 的问题不会被补进转账的句子。
- **检测**
  - 每个要点用正则判断有没有讲到。卡片里讲了，或者候选人在这道题里已经说过，就不补。
  - 补上的句子也算已经说过，后面的要点不会再重复。
  - 每张卡最多补 3 句，句数上限相应放宽。
- **按哪道题补**
  - 先看卡片自己写的 HEARD，即模型认为在回答哪道题。HEARD 匹配不上任何规则时，才看面试官最新的话。

测试过程中修掉的问题：

| 问题（哪一轮发现） | 修法 |
| --- | --- |
| W7 检查“是否已说过”时看的是整场面试，W3 说过的“对账”“恢复”被算成 W7 已经讲了（1233） | 只看面试官这道题之后候选人说的话 |
| W3 补上了“幂等契约”，又漏了“重复提交返回原交易、账本只有一笔”（1233） | W3 规则加上这一点 |
| W1 没问账本是否为权威（1233） | 加澄清规则；1339 又漏了 MVP，也一起补 |
| P2 的卡片把“怎么知道有效”推到下一张卡，下一张卡又没讲；只补一句“局限”就没头没尾（1307） | 缺证据来源时，补一句同时讲来源和局限 |
| W2 没说服务端账本是权威（1307） | 加架构图规则 |
| 模型把 W6 答成了 W5，代码按面试官的话给它补了一句群聊（1339） | 按卡片自己的 HEARD 选规则 |

测试：`scripts/test.sh` 690 项全部通过，其中 `CoachRequiredPointsTests` 11 项，用的是这几轮真实漏点的卡片。

## 结果

数字是严格评委的通过数（共 21 题），格式为“第一张卡 / 按实际念出”，Q-close 都按惯例算通过。

| 轮次 | 代码 | 严格评委 | 图 | 首字中位数 | 卡片稳定（中位 / 最慢） |
| --- | --- | --- | --- | --- | --- |
| 1139 | 修复前 | 12 / 15 | 4/4 | 645 ms | 5.5 / 8.8 s |
| 1233 | 第一版 | 17 / 17 | 4/4 | 802 ms | 6.1 / 8.3 s |
| 1307 | 加 W3、W1，缩小“已说过”的范围 | **19 / 19** | 4/4 | 849 ms | 6.0 / 9.3 s |
| 1339 | 加 P2、W2 | 17 / 18 | 3/4 | 795 ms | 5.6 / 95.9 s |
| 1413 | 加 HEARD 选规则、W1 的 MVP | 17 / 18 | 3/4 | 1045 ms | 6.1 / 28.4 s |

说明：
- 1139 的数字含重评（W2-seq 通过，W4 失败）。
- 1413 轮驱动多了一个改动：念完最后一句后，等正在生成的更新完成再结束。结果念卡时的更新从每轮 6–9 次涨到 81 次，请求从约 200 次涨到 488 次。这一轮的“按实际念出”和其他轮不能直接比。P1 没有任何补漏规则也出现了 5 次更新，说明是驱动造成的，不是 app。1339 的驱动是参考版本。
- 1339 的最慢 95.9 s 见下文 W6。

## 仍未解决

- **W6 不稳定。**
  - 1339：DeepSeek 把 W6 答成了 W5（HEARD 还是切换账号），之后面试官没再说话，app 就没再请求，卡片停了 96 s，直到候选人开口才更新。
  - 1413：卡片答对了题，但没画流程图，没问金额，也没说服务端把授权绑定到具体参数。
  - 这两次都是模型自己的问题，补漏代码管不了。下一步可以考虑：卡片的 HEARD 和面试官的新问题明显不一致时，带上新问题重试一次。
- **W1 的漏点会轮换。** 每轮漏的不一样：账本权威、MVP、外部通道或币种。如果每一条都在代码里补，卡片就会变成一串问题。
- **W7 的发布前检查**（丢响应加杀进程、重放、并发、切换账号）在 1339 漏了一次。没有加规则，因为再加一句，W7 的卡片会超过 3 句补充。
- **补上的句子会被下一张卡复制。** 1413 的 W6，“下一步”卡片把补上的那句工具调用又说了一遍。
- **P2-change 偶尔编数字。** 1413 编了“重试两次”，资料里没有这个数字。
- **固定句式。** 补上的句子是固定英文句子，每场都一样。好处是要点准确，代价是同一场里可能显得生硬。
