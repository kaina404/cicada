# ActAI 钱包面试：念卡更新计分复测

2026 年 11 月 19 日。Cicada macOS Dev 1.10.1，`36a00c5`，按当前源码重新编译（1101 轮的 app 早于最后两条提示，这一轮才把它们编译进去）。题档、Founder 动态追问、两处改题和严格评委都与 [1101 轮](../wallet-live-20261119-1101/report.md) 相同。面试官用真实声音（`AUDIO=1`）。

## 这次改了什么测法

- **念卡过程中的更新也计分。** 候选人念卡时如果卡片更新了，就接着念新卡里还没念过的句子。每题出两个分数：
  - “第一张卡”只评第一张稳定的卡片加一次“下一步”，和 1101 轮的口径一致；
  - “按实际念出”评候选人实际念出的全部内容。

## 驱动的问题（已修）

W2-seq 和 W4 两题，驱动在 1.1 s 时就拿到了一张“稳定”的卡片，但那其实是上一题念卡时的更新，正好在面试官提问的过程中生成完。查调试日志，app 其实正确回答了这两题：
- W2-seq：第 109 号请求，画了时序图；
- W4：第 150 号请求。

我用这两张真实卡片重新评分，结果写在 `interview.json` 的 `regrade` 字段里：
- **W2-seq 通过**，图也画对了；
- **W4 仍然失败**：没说“两个转账意图各有独立 ID”，也没说“在同一个事务里检查并扣减余额”。

不过这两题候选人念的都是错卡，所以“按实际念出”的分数反映不了念卡时的更新。

这一轮的 [driver.py](driver.py) 保留原样；修复写在 [1233 轮的 driver.py](../wallet-live-20261119-1233/driver.py) 里，之后各轮都用它：
- 面试官开口前，先等教练连续空闲 4 s（最多等 30 s）；
- 如果稳定下来的卡片仍然在回答上一题，就继续等新的请求。

## 结论

- **最后两条提示生效了。**
  - W2 的流程图把客户端画成 Screen → ViewModel → Repository → Local DB 四个框；
  - W2-seq 的真实卡片写出了余额数字（A 剩 20 美元、B 得 80 美元），也有确认步骤，严格评委判通过。
- **1101 的测试盲区确实存在。** W1、W2-design、P3-risk 三题，第一张卡漏点，念卡过程中都补上了。按候选人实际念出的内容评分，比只看第一张卡多过 3 题。
- **固定漏点里，这几个不是念卡更新能补上的。**
  - W6：工具重复调用对应原来的转账意图，又漏了；
  - W7：什么时候恢复，又漏了；
  - P2-alt：证据能证明什么、不能证明什么，又漏了；
  - 这一轮新冒出来的漏点：W3 的“只在契约允许时重放”、W4 的“独立 ID + 同一事务”、W5 的“从 A 的历史恢复”。

  这几题念卡时卡片都没有更新，而这些要点都在话题提示里。说明 5–6 句的长度确实装不下全部要点，所以改在代码里补漏，见 [1413 轮报告](../wallet-live-20261119-1413/report.md)。
