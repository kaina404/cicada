# Mac 全文面试教练

2026-11-08：范围统一为「实时感知 → 完整英文回答 → 全文追踪 → 动态重规划」。不提供短语、关键词或无提示模式。仅开发 Mac，目标设备 M4 Pro / 48 GB。用户已允许合理的第三方依赖。

## 使用

在 AI 服务设置导入简历、JD、项目与公司背景，启用面试教练。配置 DeepSeek key 供 Flash 生成回答和判断原稿有效性，本机 MLX Gemma E4B 负责麦克风跟读；设置中的「安装语音检测」安装 ONNX Runtime 并准备 Silero 和 Smart Turn。无需 Terminal。打开候选人麦克风才能按实际语音追踪朗读；屏幕理解仅使用本场会议在纪要顶部选择的窗口或屏幕，选择可跳过，声音沿用当前来源。新会议不沿用上一场的选择；结束会议时停止捕获并清除预览、关键帧与未完成的屏幕读取。模型未就绪显示设置状态，失败显示重试；语音模型不可用时退回文本判停。

每次输出可直接朗读的完整英文回答，B1–B2 难度、短句、结论先行。按中国大陆高三英语水平减少音标：常用词不标，专业词和较难词优先，同词每篇仅标首次。随 App 打包英式 IPA 离线词典，以熟词表和词长作轻量筛选，不当作官方课程分级，未收录的词不猜读音。流式输出等词完整后再标注，代码与网址不标注；跟读与本机中文对照忽略音标。可选中文对照使用已有本机翻译。`⌃⌥A` 手动重生成。「跟随朗读」控制自动滚动，用户可暂停跟随回看全文。

## 处理与不变量

系统音频和麦克风分别输入 Apple SpeechAnalyzer；不把两路混合后猜身份。系统音频归面试官，麦克风归候选人。Silero 为每路保留独立状态，在 CPU 上运行；Smart Turn 在停顿后判断语义结束。文字规则只提供回退判停与 ASR 去重；DeepSeek 根据对话、实际发言、当前答案和未读部分判断是否存在未覆盖的要求，不用关键词决定改稿。

自动回答合并面试官增量并等待判停。已有可见稿件时，新的发言不直接取消补全；补全结束后先由 AI 审查覆盖情况，返回 keep 时不改稿也不返回新正文，replace 时在同一响应中流式输出新的剩余回答；不再使用本机审查或第二次生成调用。审查内容不显示为正文；错误、超时、过期结果与审查期间变化的实际发言均不能覆盖原稿。候选人朗读不会打断全文流式补全。屏幕变化继续合并处理。

`CoachScript.committed` 只接受最终 ASR 的实际发言，按行 ID 去重并保持不可变。Apple 增量 ASR 可以撤回，仅用于原文上下文与回声过滤；当前句光标由本机 Gemma 麦克风音频识别推进。生成文本从不自动变成实际发言；生成期间麦克风音频保留最近十秒，完成后由 Gemma 处理，不从每次增量中删除文字。全文稿件在同一回答内保持原位，仅独立的朗读进度向前推进；最终 ASR 不删稿，增量 ASR 回退不拉回光标。识别不匹配不能证明候选人改变了回答方向，因此不再触发自动重写；实际发言仍完整保留。新的面试官问题或手动重新生成可以替换稿件；屏幕变化只更新下一次请求的素材，不单独触发重写。

请求包含最近三张压缩关键帧及 Vision OCR、约 18,000 字符双方原文与最近问题、检索所得最多 6,000 字符背景和最多 8,000 字符 committed。完整原文及实际已说内容仍保存在会议记录。背景当前采用本机词项相关度检索，支持长文件后部资料；不声称已实现向量数据库或跨语言语义召回。

## 模型与资源

回答模型为 DeepSeek Flash；本机跟读模型为 `mlx-community/gemma-4-E4B-it-qat-4bit`，本机 `127.0.0.1:18765` 的 mlx-vlm 服务。已有内存前缀缓存上限 2 GB、256 token 检查点，磁盘缓存关闭。面试原文、背景和所选截图发送云端；本机保留候选人音频跟读。26B A4B 的实际峰值内存、音频/视觉兼容和响应时间尚未在该 App 测量。

新增 Python 依赖 ONNX Runtime 1.24.1，复用 MLX 环境的 NumPy、Transformers 和 huggingface-hub。声学模型版本、下载校验、许可证和协议见 [Resources/coach/README.md](../Resources/coach/README.md)。初次安装下载模型不包含会议数据；声学处理不落盘音频。Gemma 跟读推理留在本机，回答与有效性由 DeepSeek 处理；字幕翻译和纪要使用各自服务设置。

### 2026-11-08 延迟断句串线修复与 Gemma ASR 探针

- 直接证据来自开发版会议 `20261108-082855/coach.jsonl`：42.11、112.85、187.90 秒时，候选人断句合并后的原文被记录为面试官 continuation，随后启动 speculation 并替换稿件。

### 2026-11-08 候选人 Gemma 原声跟读

- 用户明确选择本机 Gemma。候选人麦克风 PCM 由 `appendCandidateAudio` 单独进入 `CoachReading`，与面试官原声音轨隔离，不上传云端。Apple SpeechAnalyzer 仍写会议原文和 committed、参与回声过滤，但不再参与高亮、光标和自动滚动；这一点包含流式更新后的进度重算。
- 两阶段生产请求：Gemma 首先只接收原声，不看稿件，转写可听见的英文；随后 Gemma 把实际转写与有编号的稿件窗口对齐，返回 through/confidence。这样避免直接把稿件与音频混合时的稿件补全倾向；第一次试验中，直接音频+稿件的静音样本确实错误输出了整篇“已读”，因此该方案未接入。
- 仅保留最近十秒 PCM，至少约 0.6 秒新非静音或停顿后的短片段触发；有单独模型请求在运行时合并后续音频，最短请求间隔 1.5 秒。完全静音不请求；纯音可得到空转写（MLX 即时结束时 content 为 null，按空转写处理）。先转写，再对齐，共两次串行请求，不保证实时逐词显示。
- 仅推进当前 answerID，永不后退；低置信度、越界、缺少词项依据、超出语音长度的跳跃均不推进。允许误读末词时由附近词项支持对齐；重复前句不能跳过后文。每次请求最多看前方六十词、后方五十词，音标先移除。
- 新问题或手动生成取消跟读任务，回答生成优先；完成后再处理有界积压音频。跟读开始前中断背景屏幕推理，屏幕工作看到跟读 busy 时也暂停。停止、会议切换和新 answerID 清空旧音频并拒收迟到结果。
