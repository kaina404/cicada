## 1. 背景（v1 基线，改动前的样子）

以下是 v1 的做法，用来说明为什么要改；现在的进度见第 0 节。会中问答（快捷键或笔记窗口「问」）用本机 Gemma 4 E4B（mlx-vlm，`VisionServer`）回答会上刚被问到的问题，全程不出本机，不走 `LingClient`。

| 环节 | 现在的做法 | 代码 |
|---|---|---|
| 问答输入 | **只有文字**：system + user 两条消息。user = `<background>`（话题、最近一条屏幕行的「含义」≤400 字、最近 60 秒发言）+ `<question>`（对方 20 秒内的话 + 未说完的半句） | `Ask.swift` `AskEngine.stream` / `AskPrompt.request` |
| 读屏输入 | 图片（JPEG 长边 1600）+ OCR 原文 → JSON `{slide,title,meaning,uncertain}` | `ScreenNotes.swift` `explain` |
| 读屏时机 | 每 1 秒截一帧；画面**静止 1 秒**（`steady == 1`）且与上次读过的帧差异 > 0.06 才读；OCR 与上一页相似度 ≥ 0.8 则不记新行 | `ScreenWatch.run` / `novel` |

实测（M4 Pro 48GB）：问答首字 0.4–0.6 s、全程约 2 s；读一页约 3.6 s；mlx 进程约 7 GB。

**已知问题**
- 问答看不到图，只能看到上一页的一句「含义」，图表细节问不出来。
- 60 秒背景太短，几分钟前提到的需求、数字会被忘掉。
- 读屏漏更新：画面持续变化（滚动文档、播放动画、鼠标一直在动）时 `steady` 永远到不了 1，一页都不读；小幅变化（表格改一格、滚动几行）差异 < 0.06，不会重读。

## 2. 目标与非目标

**目标**：在不明显拖慢首字的前提下，提高回答的准确性和覆盖面。

**非目标（本版不做）**：云端模型、打字提问、模拟面试、Intel 与其他平台的移植（其他平台只需能读懂新的记录格式，见 P0-5）。自动检测提问、持续辅助见第 7 节。

**定位**：这是用户自用的会议助手，不是一问一答的工具。它持续跟着会议走，主动给出帮助；按键提问保留，作为手动入口。

## 3. 需求

优先级：P0 = 本版必做（用户指定），P1 = 本版建议一起做，P2 = 后续。

### P0-1 回答时附上最新一张屏幕图

- 问答请求的 user 消息改成多段内容：先放 `image_url`（JPEG base64），再放现在的文本（格式与 `ScreenNotes.explain` 一致）。
- **选哪张图**（按顺序取第一张可用的）：
  1. `ScreenWatch` 最新截到的一帧，且是 ≤ 2 s 前截的（需新增一个属性，保存最新整帧，或已编码好的 JPEG）。前提是这一帧不是视频宫格（沿用 OCR 字母数字 ≥ 20 的判断；不想在提问时跑 OCR，就用最近一次读屏结果的 `slide` 判断）。
  2. 否则用最近一条屏幕行的截图，且须 ≤ 5 分钟前。`TranscriptLine.shot` 是相对会议目录的路径（如 `screens/0125.jpg`，由 `SessionStore.saveShot` 写入）；更简单的做法是让 `ScreenWatch` 在内存里留住最后一页的 JPEG。
  3. 都没有就不带图，行为与现在一致。
- **尺寸**：问答用的图要比读屏的小。默认长边 1280，以实测为准：带图后首字 ≤ 1.2 s（M4 Pro，开发版同时在听）。超标就降到 1024 / 896；仍超标，在 PRD 回执里报告数据，不要擅自砍功能。
- **隐私**：「屏幕识别」开关关着时，问答**不许**自己截屏。图只发往本机 `VisionServer.base`。
- system 提示里补一句：图是当前共享画面；回答中的数字以 `<background>` 里的 OCR 原文为准，不得自行换算。
- 文字背景里的 `Screen:` 行保留：图看不清时它是兜底，也让数字有据可查。

### P0-2 聊天背景默认取最近 5 分钟

- `AskPrompt.background` 从 60 改为 300。
- **加字数上限**：发言部分最多 4000 字（中日韩字符按 1 计），超出时从最旧的开始丢。原因：上下文一长，Gemma 容易写成「你可以这样答」（v1 测出来的坑，靠 `<background>/<question>` 标签压住），所以长背景也要实测。
- `<question>` 的判定不变（对方 20 秒内的话）。
- 把 300 和 4000 写成 `AskPrompt` 的常量，不进设置页（不加没人要的配置项）。

### P0-3 读屏兜底：至少每 5 秒更新一次

范围：会议进行中（正在听、「屏幕识别」开着，即 `ScreenWatch` 运行时），屏幕内容至少每 5 秒检查一次。

- **不能**每 5 秒调用一次 Gemma：读一页 3.6 s，模型会被占用七成以上；问答又和读屏共用同一个 mlx 服务，问题一来就得排队，首字会被拖到 3–4 s。
- **做法：两级检测。**
  1. 距离上次读屏 ≥ 5 s，且这段时间画面有过任何变化（差异 > 0.015），就**只跑 OCR**（Vision，本机、便宜），不管画面是否静止。
  2. OCR 结果相对上一页 `novel(...)` 为真时，才调用 Gemma 读这一页，并记一条新的屏幕行。不 novel 就什么都不做。
- **问答优先**：问答进行中（`AskEngine.isBusy`）不发起新的读屏；正在读屏时来了问题，取消读屏请求（URLSession task cancel），不要排队。
- 原有的「静止 1 秒 + 差异 > 0.06」触发保留，兜底只是额外加的一条路。
- 日志：`screen: fallback ocr`、`screen: fallback read`，便于在 `/tmp/livesubs-dev-debug.log` 里核对频率。

### P0-4 英文回答，下面附苹果本机翻译的中文对照

- **模型只输出英文**：`AskPrompt.system` 里的 `Reply in \(language)` 改成固定英文，不再跟随纪要语言（`notes.language(id)`）。`AskTests` 里对应的断言一起改。
- **中文不让模型写**：每一行（`Q:`、事实要点、建议）在模型流式写完后，交给 Mac 本机翻译（Apple Translation，`TranslationSession`）译成简体中文，显示在英文下面，用灰字 `#6B7080`、小一号。
  - 复用 `Translator.swift` 里现有的 `viaApple`（目前是 `private`，按需开放或抽一个小函数），**不得**走 Google 或 Ling：这段内容不出本机。
  - 一行英文写完（遇到换行）才翻这一行，不对半截句子反复翻译。
  - 术语保持原文：Jetpack Compose、Binder、Coroutine、RAG 这类词在中文行里也不译。苹果翻译可能会把它们译掉；做不到稳定保留就接受现状，并在回执里举例说明，不要另写一套术语替换逻辑。
  - **翻译不可用时**（macOS 26 以下，或系统没装中英语言包，即 `LanguageAvailability` 不是 `.installed`）：只显示英文，不报错，不弹窗。日志写 `ask: zh gloss unavailable`。
- **设置**：加一个开关「显示中文对照」，默认开。不加“回答语言”选项（固定英文，不加没人要的配置）。
- 第 7 节持续助手的所有卡片（回应建议、局势卡、术语卡等）都用同一规则。

### P0-5 AI 回答写进时间线，顶部同时显示当前回答

**要什么**
1. 实时转录 / 翻译的时间线里，除了「你」「说话人1/2」「屏幕」，新增一种「AI」行：回答写完后插入时间线，并随会议记录保存。
2. 笔记窗口顶部的回答卡片（`AskCard`）照旧实时流式显示**当前**这次回答；写完后不消失，一直显示到下一次回答替换它，或用户手动关掉。

**记录格式**（数据模型变更；其他平台必须能逐字节读写）
- `TranscriptLine.speaker = "ai"`，`SessionStore.swift` 里加 `var isAI: Bool { speaker == "ai" }`。`id` 前缀用 `a`（如 `a12`），与 `s` 屏幕行同一个计数器 `lineCounter`。
- `src` 存英文回答：第一行是 `Q: …`，下面是 `- …` 要点和 `> …` 建议，与模型输出的格式一致。`dst` 存中文对照，逐行对应（P0-4）。中文对照还没翻完时先写 `nil`，翻完再更新这一行。
- 时间 `t` 取**提问时刻**（按键时刻，或第 7 节触发时刻），并沿用屏幕行的规则：`t = max(提问时刻, 最后一行的 t)`。原因见 `AppModel.startScreen` 里的注释：纪要按行号记录已覆盖的行，不能插到已经记过的行前面。
- 只有写完的回答才落行；被取消或失败的不落。按键再问同一个问题，产生新的一行，不覆盖旧的。
- 第 7 节持续助手中，**只有回应建议**落行。局势卡、术语卡等只留在助手信息流里，否则一小时会多出几十行，把真正说过的话淹没。

**哪些地方要把 AI 行当作“不是会上说的话”**：逐个检查现有的 `isScreen` 调用点，每处都要决定 AI 行怎么处理，不能漏。

| 位置 | AI 行的处理 | 原因 |
|---|---|---|
| `Notes.swift` `prompt`（交给 Ling 写纪要） | **排除** | 否则 AI 的建议会被写成会议结论 |
| `Ask.swift` 背景与提问判定、`Copilot.swift`（`CopilotRules.needsResponse`、`terms(in:)`、`observe`） | **排除** | 否则会自己回答自己：`needsResponse` 现在只排除 `"me"` 和 `"screen"`，AI 行以 `Q: …?` 开头，一落行就会触发新的回应建议，形成死循环。之前的问答通过 P1-3 的 `<previous_answers>` 传入 |
| `SpeakerID.swift`（声纹编号、`runStarts` 等） | 排除，单独作为一个 run key `"ai"` | 它没有声音 |
| `SessionStore.swift` SRT 导出 | 排除 | 跟屏幕行一样，不是听到的字幕 |
| `SessionStore.speakerName`、文本 / Markdown 导出 | 保留，标签 `AI` | 回看时要能看到 AI 当时说了什么 |
| `Views.swift` `quoteRow` 及其他时间线行、`NotesViews.swift`、`SpeakerViews.swift`、`RecordList.swift` | 显示标签「AI」 | 见下方的显示规则 |
| 翻译流水线（Google / Ling） | **不得**处理 AI 行 | 中文对照只走本机翻译（P0-4） |

建议加一个 `var isSpoken: Bool { !isScreen && !isAI }`，“只要会上说的话”的地方都用它，免得以后再加一种行时又要逐处补。

**显示**
- 标签「AI」：字号 11、semibold，颜色 `Palette.secondary`，与「屏幕」一致。**不用**橙色 `#E8552B`：橙色只表示“正在进行”。
- 正文：英文用 `src` 的样式；中文对照用 `dst` 的位置，样式与普通翻译行相同。「显示中文对照」关掉时不显示 `dst`。
- 新 UI 文案「AI」按 AGENTS.md 处理本地化（`scripts/strings.py`）。

**其他平台**：`windows/` `android/` `linux/` 至少要做到读到 `speaker == "ai"` 不崩溃、标成「AI」、不送进纪要和翻译。写入不用做（这些平台没有会中问答）。这是记录格式的约定，Mac 先改，各平台跟进，在各自的 AGENTS.md 里记一笔。

### P1-1 带上最近几页屏幕，不只最后一页

讲者翻页很快，问题常常指向上一页。背景中改为最近 3 条屏幕行（≤ 5 分钟内），每条 ≤ 300 字，旧的在前，标注「Screen (n min ago)」。

### P1-2 带上更完整的纪要，不只话题标题

现在只传 `topics.suffix(6)` 的标题。`MeetingNotes`（`Notes.swift`）里已有 `summary`、`topics[].summary/points`、`conclusions`、`todos`、`terms`，改为传：`summary` + 最近 3 个话题的 summary + `conclusions`，总长 ≤ 800 字。这样 5 分钟以前的内容也有线索。

`terms`（纪要里的术语表）单独放一行 `Terms:`，帮模型把语音识别听错的词改回来，比如 v1 测到的 Compose → Jetpack Compose。

### P1-3 本场会议之前的问答

把本场最近 3 次问答（理解的问题 + 要点）放进 `<previous_answers>`。作用：处理追问（「那第二点呢？」），避免重复作答。来源就是本场的 AI 行（P0-5），取最近 3 条。

### P1-4 让模型说「不确定」

system 提示加规则：背景和图里都没有、自己也不确定的事实，写一条「- Uncertain: …」（回答是英文，见 P0-4；中文对照里显示为「不确定」），不要编。`parse` 要能识别这一条，卡片里用灰色显示。要先在测试里写好对应的回复样例。

### P1-5 时延护栏

- 在 `ask: answered` 日志里加上 `image=<w>x<h>/none`、`ctx=<字数>`。
- 如果首字超过 2 s，下一次提问自动不带图，并在日志中写明原因。不在 UI 上提示，不加设置项。

### P2（后续，本版只列出不做）

- 会前资料：用户拖入议程或文档，本机分段检索后放进背景。
- 「换云端重答」：需要深度经验的问题（如分布式锁风险），v1 测下来本机模型会漏要点。走 `LingClient`，并须明确提示内容会出本机。
- 只截共享内容区域、剪掉视频宫格，节省图片 token。

## 4. 约束（来自 AGENTS.md，必须遵守）

- 本机模型的调用不走 `LingClient`；图片和文字只发往 `VisionServer.base`（本机），不出本机。
- 不加第三方依赖，不加 `.xcodeproj`。UI 和引擎状态 `@MainActor`。
- 新的 UI 文案（如「不确定」）中文写，用 `L()` 或 SwiftUI 字面量，然后跑 `python3 scripts/strings.py --write` 补 en/ja/ko，并检查英文界面。
- 提示词不用 `L()`，用英文写指令，回答固定英文（P0-4）。
- 用户可见的变化：`site/changelog.json` 加中文条目，`README.md` 与 `README.{en,ja,ko}.md` 同步。
- 提交：英文 Conventional Commits，一次提交一个改动；`feat:` 主题写用户得到了什么。

## 5. 验收

**单元测试**（`Tests/CicadaTests/AskTests.swift`，离线，`scripts/test.sh` 全绿）：
- 5 分钟窗口：299 s 前的行在背景里，301 s 前的不在；超过 4000 字时丢最旧的。
- 选图顺序：有新帧用新帧；新帧太旧用屏幕行截图；> 5 分钟或开关关着时无图。
- 请求体：有图时 user 的 content 是数组，第一段是 `image_url`；无图时仍是字符串。
- 兜底触发：给定一串（时间, 差异, OCR）序列，断言何时只跑 OCR、何时调用 Gemma、问答进行中不触发。把判断写成纯函数，方便测试。
- 「不确定」行能解析出来；P1-3 / P1-1 的背景格式固定。
- system 提示固定要求英文回答，不随纪要语言变化；只有写完的行才会送去翻译（纯函数：输入流式文本，输出可以翻译的完整行）。
- AI 行：`isAI` / `isSpoken` 判断；`Notes.prompt`、`AskPrompt.request`、SRT 导出、`runStarts` 都排除 AI 行（各写一个断言）；`t` 不早于最后一行；`session.json` 编解码往返后不变。

**真机验证**（`scripts/build.sh`，用 `tools/lsctl` 驱动，读 `/tmp/livesubs-dev-debug.log`）：
- 共享一页带表格的 PPT，问表格里的某个数字：答案中的数字与原文一致。
- 持续滚动一个文档 15 秒：日志里至少出现 2 次 `fallback ocr`，内容变了会有新的屏幕行。
- 4 分钟前说过的一个数字，现在问到它，能答出来。
- 首字：带图 ≤ 1.2 s，不带图 ≤ 0.7 s（各测 5 次取中位数，写进回执）。
- 关掉「屏幕识别」后提问：日志显示 `image=none`，也没有截屏调用。
- 用中文提问（纪要是中文）：回答是英文，每行下面有中文对照；英文首字时间与不翻译时相同。关掉「显示中文对照」后只剩英文。
- 网络断开时中文对照照常出现，证明翻译走的是本机。
- 问 2 个问题：时间线里出现 2 行「AI」，位置在提问时刻，带中文对照；顶部卡片显示最近一次回答，回答写完后不消失。结束会议、重新打开这场记录，AI 行还在；导出 SRT 里没有 AI 行，导出文本里有。
- 会议结束后，纪要里不出现 AI 给的建议（纪要只依据会上说的话）。
- 检查英文界面。

## 6. 回执要求

## 7. 持续会议助手

### 7.1 要什么

助手在整场会议中**一直跟着**，不用按键，自动在笔记窗口里给出帮助。典型场景：和客户讨论方案，客户追问或提出顾虑时，助手马上给出：
- 能直接答的事实要点；
- **建议怎么回应、后面怎么规划、下一步怎么推进**。

按键提问保留，用来指定“就答这个”，或者强制刷新。

> 与 v1 的差别：v1 的 system 提示写着「Never write advice on how to answer」。助手模式要放开这一条：“建议”就是它要输出的内容。v1 的教训仍然成立，**事实**和**建议**必须分开写，用不同的标签，不能让建议吞掉事实。

### 7.2 帮助类型

| 类型 | 何时触发 | 输出 | 优先级 |
|---|---|---|---|
| 回应建议 | 对方提问、追问、提出顾虑或异议 | `Q:` 对方真正在问什么 → `- 事实` ≤3 条 → `> 建议` ≤2 条（怎么回应、下一步、可以承诺什么、先别承诺什么） | 先做 |
| 局势卡 | 约每 60 秒；话题切换时立刻触发 | 现在在谈什么、对方最关心什么、还没解决的问题、建议推进的下一步，各 1 行 | 先做 |
| 术语卡 | 生词或缩写第一次出现（复用纪要的 `terms`，加上规则识别） | 一行解释，同一个词只出一次 | 先做 |
| 新页讲解 | 读屏得到新的一页 | 这页的重点、和刚才讨论的关系 | 第二批 |
| 跟进提醒 | 有人点名让我做某事；对方的问题过了 2 分钟还没人回应 | 一行提醒 | 第二批 |

### 7.3 怎么跑

**事件驱动 + 定时兜底，不是每句话都让模型想一遍。**

1. **规则层**（每句话识别完就跑，纯函数，必须可测）：判断这句是不是**对方**在提问或表达顾虑（问号、吗/呢/怎么/为什么/能不能/what/how/why/concern…，且 `speaker != "me"`），有没有第一次出现的术语，有没有点到用户的名字。命中就把对应的任务放进队列。
2. **会议状态**：在内存里维护一个小结构 `{话题, 对方关心的点[], 未解决的问题[], 已解释术语[], 已给过的建议[]}`，每次出局势卡时更新。每次调用模型都带上它和最近 5 分钟的原文（第 3 节 P0-2），所以背景短而准，也不会重复给同一条建议。
3. **队列与优先级**：按键提问 > 回应建议 > 局势卡 > 术语卡 > 新页讲解；读屏排最后。同一类型来了新任务，就取消还没出结果的旧任务，只答最新的。
4. **防抖**：对方连续说几句话时，等这段停顿约 1.5 秒（或出现“我说完了”这类结束信号）再出回应建议，避免话说一半就开始答。

**模型：先只用一个 Gemma 4 E4B，跑通后看效果再决定是否换。**
- 所有帮助都用同一个模型，即现有的 `settings.screenModel`（读屏也用它），不另开第二个模型服务。
- 不得写死模型名。代码只认 `settings.screenModel`；将来换模型，就只是改这个设置（例如改成 Gemma 4 26B A4B 的 MLX 4bit 版本），代码不用动。
- 提问领域以计算机为主：AI 模型、Android 项目、Android 编程知识与原理。为此建一套离线评测题（见 7.6），之后换模型时用同一套题对比，不凭感觉判断。

### 7.4 怎么显示

- 笔记窗口加一个「助手」信息流，新内容在最上面。窗口仍是不抢焦点的面板，遵守现有的 `sharingType` 规则。
- 回应建议卡片用强调色 `#E8552B` 标出，其余卡片用灰字。
- 每行英文下面跟一行中文对照（P0-4），可在设置里关掉。
- **打扰上限**（体验参数，先给默认值，后面再调）：同一时间最多 1 张强调卡片，两张强调卡片之间至少隔 20 秒，局势卡至少隔 60 秒；超出上限的照样生成，只是不强调。
- 卡片可以一键收起；会议结束后信息流丢弃。只有回应建议以 AI 行的形式留在会议记录里（P0-5），其余卡片都不进 `session.json`。
- 设置 › 屏幕识别页（或另起「会议助手」区域）加一个开关：持续助手，默认开。

### 7.5 提示词要点（英文写，回答一律英文，中文对照见 P0-4）

- 角色：你是用户在客户会议里的助手，用户代表己方。
- 输入标签：`<state>` 会议状态、`<background>` 最近 5 分钟、`<screen>` 屏幕文字 + 图片、`<trigger>` 这次为什么叫你（提问 / 顾虑 / 定时 / 术语）。
- 输出：固定行前缀（`Q:` `- ` `> `），方便 `parse` 流式解析。
- 只用背景里有的事实；不确定就写「不确定」。建议要具体可执行，不要空话（“加强沟通”这种不行）。
- 不替用户做承诺：涉及价格、工期、合同条款的，只建议“怎么回应”，不编具体数字。

### 7.6 验收

- **单元测试**（离线）：规则层，给 30 句中英文样本（提问、顾虑、陈述、我自己说的），判断准确；队列的优先级和取消；打扰上限的节流；`parse` 能区分事实行和建议行。
- **真机**：用 `say -o` 做一段约 5 分钟的“客户讨论”音频（含 4 个追问、2 个顾虑、3 个术语），`afplay` 播放：
  - 6 个追问和顾虑中至少 5 个自动出了回应建议，从对方说完到首字 ≤ 2 s；
  - 不出现重复的建议；陈述句不触发回应建议；
  - 局势卡每分钟约 1 张，内容跟得上话题切换；
  - 播放期间按键提问仍然最先被回答。
- **评测题**：`tools/` 下放一份约 30 题的题库（JSON），覆盖 AI 模型（训练、推理、量化、RAG、Agent）、Android（生命周期、Compose、协程/Flow、Gradle、性能、内存泄漏、Binder 等原理），以及几道带客户追问语境的题。每题附要点清单。再加一个脚本：对本机 mlx 服务跑一遍，输出每题首字时间、全程时间和回答原文，由人对照要点清单打分。不进单元测试（单元测试要离线），作为手动工具使用。
- 回执写明：E4B 在评测题上的结果（首字、全程、明显答错或漏要点的题）、整场的 GPU 和内存占用、误触发和漏触发的例子。
